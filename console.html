Se connecter à votre dépôt

Le jeton sert à enregistrer vos décisions et à lancer les actions d’ici. Il ne quitte jamais votre navigateur : il est rangé dans le stockage local de cette page, sur cette machine. Ni moi ni personne ne le voit. Ne le collez jamais dans une conversation.

Je n’en ai pas — le créer en une minute
  1. Ouvrez github.com/settings/personal-access-tokens/new (ou : votre photo → Settings → Developer settings, tout en bas → Personal access tokens → Fine-grained tokens)
  2. Token name : curio-console
  3. Expiration : 90 jours. Vous le refabriquerez en une minute.
  4. Repository access : Only select repositories → choisissez votre dépôt curio.
  5. Permissions → Repository permissions, deux lignes à passer sur Read and write :
    Contents  et  Actions. Laissez tout le reste sur No access.
  6. Generate token, puis copiez-le : GitHub ne le montre qu’une fois.
  7. Collez-le ci-dessous, et Enregistrer et vérifier.

Ce jeton ne peut rien faire d’autre que lire et écrire dans ce dépôt-là, et lancer ses actions. Il ne donne accès ni à vos autres dépôts, ni à votre compte. Si vous le perdez ou le doutez, révoquez-le sur la même page : rien n’est cassé, vous en refaites un.

Vous pouvez aussi vous en passer. Sans jeton, la console montre tout et garde vos décisions dans ce navigateur ; le bouton Télécharger decisions.json vous donne le fichier, que vous déposez sur GitHub par Add file → Upload files. Le résultat est identique — ce sont ces fichiers que les outils lisent.

Agrandir le catalogue de sujets

La moisson parcourt Wikipédia et ajoute des SUJETS — pas des textes. Elle ne coûte rien : aucun appel payant. Un sujet déjà présent garde son état ; relancer n’écrase jamais rien.

Mettez « non » quand vous avez plus de sujets d’avance que vous n’en écrirez ce mois-ci. Un lancement à la main passe toujours outre ce réglage.

Valider ne publie rien : c’est votre jugement de lecture, gardé dans ce navigateur puis dans validations.json. Envoyer au stock transforme ce jugement en réserve prête : les fiches validées prennent la marque prête à publier, et 5 · Publication les sort ensuite au rythme réglé. Rien ne va en ligne avant ce moment-là.

Pourquoi ces chiffres ?

Ce que disent vos fiches — ce que le lecteur reçoit — et ce que dit le catalogue, côte à côte. Rien n’est modifié, rien n’est demandé au réseau. S’ils ne concordent pas, la ligne du bas le dit.

Vérifier avant de publier

Cinq outils, tous gratuits et tous sans destruction : ils lisent, ils rapportent, et ne modifient que si vous le demandez explicitement.

Repartir de zéro sur la mise en ligne

Tout renvoyer au stock dépublie l’ensemble de vos fiches : elles repassent en réserve, avec leur note, leur relecture et leur marque de contrôle intactes. Aucun texte n’est effacé. Ce n’est pas un retrait — un retrait sort une fiche pour de bon ; ceci la remet dans la file d’attente.

Le site se vide jusqu’à votre prochaine publication. À faire quand vous voulez reprendre la main sur l’ordre de sortie.

Le rythme de sortie

Les fiches sont écrites d’avance et gardées en réserve. Ces réglages disent quand elles sortent et combien. L’action tourne tous les jours à 6 h UTC ; c’est ce que vous réglez ici qui décide si aujourd’hui compte.

Sortir des sujets choisis, maintenant

Cochez dans votre réserve ce que vous voulez mettre en ligne aujourd’hui, quel que soit le rythme réglé au-dessus. Un sujet sort avec toutes ses langues publiées. Ce qui est en quarantaine ne sort pas : validez-le d’abord.

Essayer l’application

Ouvrez l’application dans l’état que vous voulez vérifier. Le réglage ne vaut que pour ce navigateur : personne d’autre n’est concerné, et vous revenez au gratuit quand vous voulez.
